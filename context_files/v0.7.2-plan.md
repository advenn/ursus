## The synthesizer's plan, as it wrote it

This plan merges the seven area reports (H0+H7, H1, H2, H3, H4, H5+H6, H8+H9) on `hunt/0.7.2-scope` (f97ad9c). The agents behind those reports did the reading and probing. I built and ran nothing. I re-read the code behind the claims that set the order (i128.go:405-462, csv scanner.go:315-330 and split.go:230-242, pages.go:222-240, fromrows.go:116-215, nbytes.go:108-117, column.go:1125-1155, budget.go:262-272/355-362). I also diffed a few files between the two lines and confirmed that PR #1 is still open. Two corrections came out of that, listed under "Corrections".

### How to read it
- **One step, one PR.** Each numbered step is one branch off `release-0.7` and one PR into it. The exceptions are marked *(maintainer action)* or *(PR into master)*. Every step assumes PR #1 (step 410) is merged.
- **Needs** lists the steps that must merge first. Anything not listed can run in parallel. **M3 starts once M1 is in, without waiting for M2.**
- **Size.** S is under half a day, M is a day or two, L is several days. These are agent time, before review.
- **Runs.** *laptop* means at most one targeted `go test` with `GOFLAGS=-p=1 GOMAXPROCS=4`, plus `GOAMD64=v3` where bits matter. *ci* means per-PR CI. *nightly* needs your yes. *maintainer* means you do it.
- **D-numbers** refer to the decisions list near the end.

### Rules that apply to every step (stated once)
- **Checklist.** Each PR follows 413's checklist:
  - a test-only commit that fails, then the fix;
  - the outside answer (engine, version, snippet) or a §9 ID;
  - the teeth line;
  - the gate: `./internal/...` and the root package in full after the last edit, with `df` before it and widths and race left to CI;
  - the API diff green;
  - a CHANGELOG 0.7.2 "Fixed" bullet and an as-built record;
  - `gh run list` after each push;
  - no session URLs in commits or PR bodies.
- **Forward-ports.** Once a release PR squash-merges:
  1. Branch `fwd/<topic>` from origin/master.
  2. `git cherry-pick -x <sha>` and open a PR into master.
  3. Put the CHANGELOG bullet under master's Unreleased / Fixed with "also in v0.7.2".
  4. Always forward the test, and show its teeth on master. Master's one-thread small queries (602bc5b) and shared budget (6e5bc55) can make a thread or spill test pass trivially there.

  Code needs re-deriving, not just applying, where master rewrote the file: execopt/budget.go, physical/extjoin.go, join.go, agg.go, parquet/pool.go, parquet.go, lazy.go, ipc.go, memlimit.go, operator.go, export_test.go, and dtype/temporal.go (one line, 8c410b9). panic_test.go, rollingmem_test.go and internal/source/csv/csv.go are identical on both lines (checked).

  Put new tests in new files named for the bug. Batching one H item's forward-ports into a single PR is fine. Not forwarded: 414 (master has its own check) and 0.7-only text. 474 is a master PR by nature. Run `make fwd-check` before the tag.
- **No public API change.** Every fix below touches unexported or internal code, doc comments, error texts or behaviour, and 414's strict diff proves it on each PR. Depth limits and allocation caps are named constants, not options, because an option would be an API addition. No step changes ursustest's behaviour. H5 works around the fact that IgnoreRowOrder cannot be combined with WithTolerance. The only steps that come near an API concern are flagged:
  - 435 edits unexported code in the public dtype package;
  - 482(b) would bump a dependency;
  - D8 and D17 would change behaviour, with no signature change.
