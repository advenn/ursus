# Tests from recorded oracles, not hand values — the scope

**Set on 2026-11-05** at the maintainer's word: "regarding tests, make it test dynamic
values, not handcrafted tests." A test whose expected value its author typed can only
restate what the author believed; one whose expected value comes from somewhere else
can catch a function built on a wrong belief. From this scope on, a test's expected
data comes from one of:

1. **a recorded oracle:** Polars 2.1.0's answer (or DuckDB's) to the same question,
   produced by a script, checked in as data, and regenerated by CI to prove it;
2. **a Go oracle:** an independent computation in the test (math/big, strconv, time,
   encoding/csv, arrow-go, a brute force) over generated inputs;
3. **a differential:** the same query another way (spilled against in memory, threads,
   optimizer off, batch sizes), over generated inputs.

What asserts a refusal, a type, a plan, a count or a resource bound stays as it is.
Hand-typed data values are not written any more, and the existing ones are replaced.

## 2. The framework (step 496)

**The format.** `testdata/oracle/<group>.json`, one file a group of cases:

```
{"polars": "2.1.0", "generator": "bench/scripts/oracle/<group>.py",
 "cases": [{
   "name": "rolling_var_ddof0_nulls",
   "inputs": {"df": {"columns": [{"name": "x", "dtype": "Float64", "values": [1.5, null, "NaN", "-0.0"]}]}},
   "params": {"window": 3, "ddof": 0},
   "want": {"columns": [...]} | {"error": {"polars": "<class>: <message>", "contains": "<ursus's phrase>"}},
   "order": "rows" | "set",
   "float": "bits" | "rel:1e-9" | "rel:1e-12 abs:1e-15",
   "note": "why this case exists"
 }]}
```

(As built: the keys are sorted, `params` and `note` are written only when set, and a
refusal records Polars' exception class and first line beside the phrase ursus's
refusal must name, "" for none.)

- **Types, every one ursus has,** spelled as ursus prints them: `Int8`…`Int64`,
  `Uint8`…`Uint64` (ursus's spelling, not Polars' `UInt8`), `Int128` (a string, past
  what JSON keeps), `Float32`, `Float64`, `Bool`, `String`, `Binary` (base64), `Date`
  (days), `Datetime(us, Europe/Paris)` (ticks), `Time(ns)`, `Duration(ms)`, `Decimal(12,
  4)` (the unscaled integer as a string), `Categorical` and `Enum(a, b)` (the text),
  `List(Int64)`, `Array(Float64, 3)`, `Struct(a: Int64, b: String)`. Nested values are
  nested JSON, a Struct an object by field name. A float is a JSON number when finite
  and not −0, else `"NaN"`, `"inf"`, `"-inf"`, `"-0.0"`; Python's repr round-trips every
  double, and a Float32 is written as the double it equals.
- **Several inputs** by name (`left`, `right`); **a whole output frame** with exact
  dtypes; **an error** where Polars refuses; **`order: set`** where Polars' row order
  is unspecified (group-by without maintain_order, joins); **`float: bits`** by
  default, −0 apart from 0 and NaN equal to NaN, a tolerance only where the case says
  why (a merge order's last bits, §1 of feature-gaps.md).
- **Generated inputs are data.** The Python side generates them from a seed (numpy's
  `default_rng(seed)`) and records them, so the Go test reads data, not code, and the
  JSON is the whole truth. Sizes of 50 to 500 rows; what needs millions of rows stays a
  Go differential.

**The Python side.** `bench/scripts/oracle/`: `__main__.py` (`python -m
bench.scripts.oracle`, from the repository root, writes every group, or the groups
named; `make oracle` runs it), `encode.py` (a Polars frame to the format, every dtype
above), `gen.py` (seeded column generators per dtype, with null rate, NaN, ±Inf, −0,
ties, the type's edges, 2^53, the epoch's edges, DST instants of named zones), and a
module a group, each a list of cases: a name, the inputs (literal or generated), the
Polars query, and the options. Polars pinned at 2.1.0 in `bench/scripts/oracle/
requirements.txt`; `oracle_expressions.py` becomes the `expressions` group, its 46
cases kept, and `expressions.json` re-recorded under 2.1.0 (step 487 said identical
to 1e-12; by bits, two ewm cases moved by an ulp, and are held to rel:1e-12 with the
reason). A `format` group, generated, puts every type through the identity, so the
encoder and the loader are proved to agree on each.

**The Go side.** In the root package, `oracle_test.go` grows a loader: the JSON to
ursus frames through the public constructors (`Values`, `ValuesNullable`, typed
columns, the nested and temporal types), a registry a group (`oracleGroups["agg"] =
map[name]func(inputs) *LazyFrame`, each group in its own `oracle_<group>_test.go`, so
groups never edit one file), the run of each case, and `ursustest.AssertFrameEqual`
with dtypes checked and floats by bits. `oracleDifferences` stays: a case whose answer
ursus gives on purpose otherwise (feature-gaps §9, step 487 §3) names its difference
and the test asserts ursus's documented answer instead. No new public API: the loader
is test code.

**CI.** `.github/workflows/oracle.yml`, on a pull request that touches
`testdata/oracle/**` or `bench/scripts/oracle/**` and on `workflow_dispatch`: install
Polars 2.1.0, run the generator, `git diff --exit-code testdata/oracle`. A recorded
answer that is not Polars 2.1.0's fails. It is not a required check of master's
protection until it has run green on three PRs.

**The pilot,** in the same step: three files converted end to end to prove the format
holds, chosen for what they need of it: `numodds_test.go` (118 hand lines; bit-exact
floats, quoted Polars errors), `rollmore_test.go` (97; bit-exact, windows),
`dtmore_test.go` (90; ns/ms/zoned datetimes, Duration totals). Each conversion: the
hand table becomes cases, with one generated case beside each literal one of the same
shape; the Go test keeps only the query registration; the hand values go.

## 4. The rule from here

A new test's expected data is a recorded case, a Go oracle or a differential. A pull
request that adds a hand-typed table of data values is not merged. `make oracle`
regenerates; `go test -run TestOracle .` checks.
