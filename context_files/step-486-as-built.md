# Step 486 — as built

**The test suite's duplicates cut.** On 2026-11-03 the maintainer asked: "reduce
tests amount. having 1000 test for single function is useless while the function
itself is built on incorrect logic." A test that restates what its author believed
cannot catch a function built on a wrong belief; one checked against an answer from
somewhere else can. So the rule for every cut was: a test goes when another test
already asserts the same behaviour against an independent answer, or when it asserts
nothing.

## 1. The inventory

Six read-only surveys classified every test file of master's `ad9056f`: 566 files,
1,744 `Test` functions, 115,631 lines.

| kind | what it checks against |
| --- | --- |
| oracle | Polars' or DuckDB's recorded answers, math/big, strconv, encoding/csv, arrow-go, a brute force |
| self-differential | the same query another way: spilled against in memory, optimizer off against on, one thread against many |
| regression | a bug that was found, pinned once |
| hand | values typed by the test's author |
| refusal, resource, guard, API | an error's kind and text; memory and files; a mechanism no public query reaches; the documented examples |

Most of the suite is oracle-backed or self-differential. The waste was:
- tests that repeat a sweep or brute force beside them;
- hand cases that repeat `testdata/oracle/expressions.json` or a closed form;
- batch-size × thread products run in full in a dozen files;
- kernel tests repeating a root test row for row.

## 2. What went

Each cut was checked against the test named as its cover, by reading both. About one
claim in four did not hold, and those tests stayed: the forward-fill
limits, `Tail`'s edges, a sliced List(String) re-lazied, the pushdown tests of
`Exact` sources, `cmpWords`' both-scalar arm, `listSort`'s argument panic.

| | functions | lines |
| --- | --- | --- |
| root package, first half (`agg` … `joinwhere`) | 26 | −1,030 +178 |
| root package, second half (`listbatch` … `zipselect`) | 28 | −1,072 +27 |
| dtype, i128, internal/... | 62 | −2,470 +272 |
| **total** | **116** | **−4,556 +460** |

After: 1,628 functions in 555 files, 111,534 lines.

Among them:
- `asof_test.go`'s manual scan, strategies, exact matches and by-groups. The brute
  force in `asofstream_test.go` runs all three strategies with by-keys, ties and
  tolerances.
- `calendar_test.go`'s nine zoned cases. `TestCalendarAgainstTheOracle` checks every
  2024 transition of seven zones.
- 11 of `ewm_test.go`'s 13 hand cases. They are covered by the closed form and the
  recorded Polars answers.
- In the root package, a join's sides and a semi join's projection, which the golden
  plans pin.
- In the kernel, the null-operand, select, cast-agreement and all-null rows. Root
  tests or `TestEvaluatorContract` repeat them.
- 11 test files went whole with `git rm`. Their tests went, or moved into the file
  beside them (the panic relays into `panic_internal_test.go`, the UDF ids into
  `identity_test.go`, `ConcatOwned` into `concatspread_test.go`).

**Sweeps.** Twelve batch-size × thread products now run three pairs: smallest size
with fewest threads, middle with middle, largest with most. Those sweeps ran 8 to 30
collections each. `countcols_test.go`'s 420 collections are 210. `invariance_test.go`'s
shared `assertInvariant` keeps its full product as the one place that sweeps it.

## 3. Checks

- `go vet ./...`: clean.
- `go test ./dtype/... ./i128/... ./internal/... ./selector/... ./ursustest/... ./docs/...`:
  ok.
- `go test .`: ok, in 245 s on the combined tree. `TestEveryCitedTestExists` is in it,
  so a comment naming a removed test would have failed it. The comments that named
  one were reworded.

## 4. Left

- **Hand tables that want an oracle:** `listns_test.go` (739 lines of null-against-
  empty by hand), `enum_byhand`, `strptime`, `topk_agg`'s `TestTopKValues`,
  `withfields`, `explode`, hive's `TestInfer`, `selector_test.go`, dtype's
  supertype tables, expr's decimal aggregate types. Each would be replaced by Polars'
  answers recorded in `testdata/oracle` and compared there.
- **Pasted answers:** most oracle files paste Polars 1.44.1's answers into the test.
  Only `testdata/oracle/expressions.json` is regenerated by a script. A runner that
  regenerated the rest would make them re-checkable against Polars 2.x (step 487).
- `TestUDFErrorIsTheSameRowAtEveryBatchSize` went because it never checked the row
  its name promises. That claim is still pinned nowhere.
- File merges that only move code between files were not done: they shrink nothing.
