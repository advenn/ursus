## 1. Generators

**The design.** A generator of scalar arguments is a column of its own length,
which 0.6.5's E4 already gives a place:

- the kernel is the per-row form, `int_ranges` and the rest, which make one List a
  row from each row's start, end and step;
- the scalar form is that list exploded over a frame of one row, the arguments'
  keyless aggregate: in `Select` and `WithColumns` a plan of its own, zipped, so
  `IntRange(Lit(0), Len())` is a row index the frame's height;
- in an aggregation it is a list a group: the per-row form over the group's scalar
  arguments.

**G1. Integer and numeric ranges:**

- `IntRange(start, end, step)` and `IntRanges`, Int64 by default with a dtype option,
  an empty range for start past end;
- `LinearSpace(start, end, n, closed)` and `LinearSpaces`, numeric and temporal;
- `Repeat(value, n)`, `Ones(n)` and `Zeros(n)`, Float64 by default.

**G2. Temporal ranges:**

- `DateRange` and `DateRanges`;
- `DatetimeRange` and `DatetimeRanges`, with a unit and a zone;
- `TimeRange` and `TimeRanges`;
- each with an interval (`Every`'s strings and `time.Duration`) and `closed` (both,
  left, right, none), calendar intervals moving the wall clock as `OffsetBy` does.

**G3. Values from their components:**

- Polars' `pl.date`, `pl.datetime`, `pl.time` and `pl.duration`, built from
  expressions, where today they are Go literals only. `Date`, `Datetime` and
  `Duration` already name the types, so these are `MakeDate(y, m, d)`,
  `MakeDatetime(y, m, d, h, mi, s, us, unit, zone)`, `MakeTime(h, mi, s, ns)` and
  `MakeDuration(weeks, days, …)`;
- `FromEpoch(column, unit)`;
- `BusinessDayCount(start, end, weekMask, holidays)`.

## 2. Folds, constructors and selection

**F1. Folds and constructors:**

- `ConcatList(exprs...)`: each row's operands in one list, a List operand's elements
  and another's value;
- `Fold`, `Reduce`, `CumFold` and `CumReduce` take a Go function from two Exprs to
  one and build the expression when the query is planned. Polars' take a function
  over Series, run per batch. Built ahead they need no UDF, and the optimizer sees
  through them. `CumFold` and `CumReduce` give a Struct of the running values, as
  Polars';
- `CumSumHorizontal`;
- `Format("{} of {}", exprs...)`: a `ConcatStr` of the pieces.

**F2. Selection and order:**

- `Nth(i...)`, and `First()` and `Last()` as column selectors, the first or last
  column;
- `ArgWhere(pred)`, a column of the true rows' indices;
- `ArgSortBy(exprs, descending, nullsLast)`, and `Expr.ArgSort`, `ArgTrue` and
  `ArgUnique`.

## 3. `List().Eval` and `Element()`

`Col("l").List().Eval(Element().Mul(2))` runs an expression over each list's
elements, the list its group. It is the general form of the list namespace:
`List().Filter(pred)` is `Eval(Element().Filter(pred))`, and `List().Agg(e)` is
Eval of an aggregate.

**The design** lowers the body by what it does to a group, as 0.6.5's E3 lowered an
aggregation's reshapes:

- **a value an element** (arithmetic, casts, string functions on Element) is computed
  over the list's elements end to end, and the answers keep the list's offsets;
- **an aggregate** is one value a list, by the accumulators over the offsets, as the
  list reductions are;
- **a reshape and a filter** are the list kernels 0.6.5 built, applied to the list
  itself, which is already a group's values;
- **a window function** over Element (`rank`, `cum_sum`, `shift`, `diff`) is
  computed a list at a time, each list a partition.

A body that reads a column other than Element is refused, as Polars refuses it.

## 4. The namespaces

**L. `.list`:**

- `Concat`, `Shift(n)`, `Diff(n)`, `CountMatches`, `Any`, `All`, `Item`;
- `Sample(n or fraction, seed)` and `Shuffle`;
- `Sort` with `nulls_last`;
- `Filter` and `Agg` (§3).

**S. `.str`:**

- **matching:** `ContainsAny`, `ReplaceMany`, `ExtractMany` and `FindMany` (each over a
  list of patterns, Aho–Corasick, ASCII case-insensitive as an option),
  `ExtractGroups` (a Struct of the named groups);
- **splitting:** `SplitExact(by, n, inclusive)`, a Struct, and `SplitN` made a Struct
  as Polars' is (§6.2); `Split` with `inclusive`;

  `golang.org/x/text/unicode/norm`, already in the module graph through arrow-go;
- **encodings:** `Encode` and `Decode` (hex, base64), to and from Binary;
- **numbers:** `ToInteger(base, dtype, strict)`;
- **options Polars has:** `Replace`'s count `n`, `ConcatStr`'s `ignore_nulls`;
- **JSON:** `JsonPathMatch(path)`, a subset of JSONPath; `JsonDecode(dtype)` with the
  type given, no inference.

**D. `.dt`:**

- `IsoYear`, `Century`, `Millennium`;
- `IsBusinessDay` and `AddBusinessDays(n, weekMask, holidays, roll)`;
- `Replace(year, month, …)`, setting components;
- `BaseUtcOffset` and `DstOffset`;
- `WithTimeUnit`;
- `TotalMilliseconds`, `TotalMicroseconds` and `TotalNanoseconds`, and `fractional`
  on every total;
- `Epoch(unit)` and `Timestamp(unit)`;
- `Second(fractional)`.

**C. `.cat`,** on Enum, the categorical type ursus has:

- `GetCategories`, `StartsWith`, `EndsWith`, `LenBytes`, `LenChars`, `Slice` and
  `Physical`;
- and `Str()` takes an Enum, read as its strings, where it refuses one today.

**B. `.bin`:** `Contains`, `StartsWith`, `EndsWith`, `Get`, `Head`, `Tail`, `Slice`,
`Size(unit)`, `Encode`, `Decode` and `Reinterpret(dtype, endianness)`.

**T. `.struct`:** `Field` of several names, written out as `Unnest` is.

## 6. Decisions

**6.1. `.arr` waits for the Array type.** 0.6.5's §5 put `.arr` here. It needs a
fixed-size list type ursus does not have: `dtype` has the constructor and nothing
stores, reads or writes one. A type is not a namespace. It goes with Categorical and
large strings, `feature-gaps.md` §3, in a release of types, after I/O. So does
`List().ToArray`.

**6.2. `SplitN` returns a Struct,** as Polars' `splitn` does, fields `field_0` to
`field_{n-1}`, null past the parts. Today it is a List. That is a break, listed with
the release. `Split(...).List().Head(n)` keeps the old shape but not its last part.

**6.3. Some answers cannot be Polars' to the bit:**

- `Hash` is its own algorithm;
- `Sample` and `Shuffle` are their own generator;
- `ApproxNUnique` counts exactly, an approximation's best case.

Their tests hold properties instead: the same seed gives the same answer, a sample is
drawn from its column, equal values hash alike.

**6.4. The list differences stay,** as `feature-gaps.md` §9 records them:
`List().Get` null out of range, `NUnique` not counting null, the sum of an empty list
null. Each agrees with the column-wide operation beside it.

## 7. Claims

For each item:

- **it answers as Polars 1.44.1 does,** checked against Polars' answers on the same
  inputs, but where §6.3 says it cannot and §9 of `feature-gaps.md` says it does not;
- **it spills or streams where its pieces do:** a generator as E4's columns, a fold as
  the expression it builds, `Eval` as the list kernels and accumulators;
- **no regression:** the 34 golden plans and the 37 benchmark queries' plans are
  unchanged, which step 261's plan diff checks again at the report.
