    Coming from Polars¶

    ursus is modelled on Polars: the same expressions, the same contexts, mostly the same names, and its answers are tested against Polars 1.44's on the same inputs. What changes is what Go asks for.

    import polars as pl

df = (
    pl.scan_csv("sales.csv")
    .filter(pl.col("qty") > 3)
    .group_by("region")
    .agg(
        (pl.col("qty") * pl.col("price")).sum().alias("revenue"),
        pl.len().alias("orders"),
    )
    .sort("revenue", descending=True)
    .collect()
)

    df, err := ursus.ScanCSV("sales.csv").
    Filter(ursus.Col("qty").Gt(3)).
    GroupBy(ursus.Col("region")).
    Agg(
        ursus.Col("qty").Mul(ursus.Col("price")).Sum().Alias("revenue"),
        ursus.Len().Alias("orders"),
    ).
    Sort(ursus.Desc(ursus.Col("revenue"))).
    Collect(ctx)

    What Go changes¶

    • Methods, not operators. Go has no operator overloading, so pl.col("a") > 3 is Col("a").Gt(3), and a * b is a.Mul(b).
    • Lazy is the real API. A LazyFrame is a query and Collect runs it. A DataFrame's methods are a lazy query collected at once, so each takes a context.Context: df.Filter(ctx, pred).
    • Errors come at the end. A query being built never fails: an unknown column or a type mismatch is kept and returned by Collect, with a hint, so a chain stays a chain.
    • Values come back typed. df.Column[int64]("qty") is a Series[int64], and df.Rows[Sale]() a []Sale, through Go 1.27's generic methods.
    • Options are functions. Join(other, JoinOn(Col("k")), JoinHow(JoinLeft)) where Polars takes keyword arguments.

    Where ursus answers differently¶

    These are deliberate, and each is documented beside the method:

    • An integer sum is an Int128, as DuckDB's is, so it cannot overflow. Polars' sum of Int64 is an Int64.
    • The sum of an all-null group is null, not 0, and its product null, not 1: a null can be filled with 0 afterwards, but a 0 cannot be told from a real one.
    • Count(ctx) of a frame is its number of rows. Polars' frame count() is each column's non-null count; in ursus that is Select(ursus.All().Count()).
    • NUnique does not count null as a value; Polars counts it.
    • Round rounds half away from zero; Polars rounds half to even, which RoundHalfToEven selects.
    • Max and Min propagate NaN; Polars' max ignores it, and its nan_max propagates it, as NanMax does here.
    • A literal has its Go value's type: Col("a").Add(3) of an Int32 column is an Int64, since a Go integer constant is an int; write int32(3) to keep Int32. Polars' literals take the column's type, as a fill value's does here.
    • A cast is exact or refused: a float with a fraction cast to an integer is an error, or null when lossy, where Polars truncates it toward zero. Truncate(0) first for Polars' answer.
    • Div and Pow always give a float.
    • An expression is named after its leftmost column. Col("a").Alias("x").Add(1) is x in Polars and a here: put the alias last.
    • Remove drops a row whose condition is null, as Filter does; Polars' remove keeps it.
    • GroupByDynamic keeps empty windows, a row of Len 0 for a period with no rows; Polars leaves them out.
    • ToInteger, ToDate and ToDatetime give null for what does not parse; Polars' fail by default.
    • Cut and Hist give text, where Polars gives a Categorical, which ursus does not have yet.
    • A Time takes a unit, where Polars' is nanoseconds.

    The full list, with the step that made each choice, is in feature-gaps.md §9, and what Polars has that ursus does not yet is in the rest of that file.
